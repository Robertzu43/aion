# Aion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build **Aion** — a personal AI daily-optimizer that ships as a **Claude Code project** (slash commands + a skill + `CLAUDE.md` + local data files), runnable under the user's Claude subscription with no API keys or backend.

**Architecture:** A GitHub repo the user clones and opens in Claude Code. Four slash commands (`/aion-setup`, `/aion-platzi`, `/aion`, `/aion-dashboard`) drive the workflow; a skill (`.claude/skills/aion/`) holds the reasoning logic; `CLAUDE.md` orients Claude Code each session. Personal data lives in a gitignored `data/` tree (JSON + Markdown); committed `data.ejemplo/` templates show the expected shape. The "brain" is Claude Code itself.

**Tech Stack:** Claude Code (slash commands as Markdown with frontmatter, skills as `SKILL.md`), JSON + Markdown data files, self-contained HTML for the dashboard (following the `dataviz` skill), Claude Code built-in `WebSearch` for news.

**Verification model:** There is no executable app to unit-test. Each task defines an **explicit artifact contract** and is verified by (a) inspecting the created files against that contract and, where a command exists, (b) running the command inside Claude Code on sample/real data and checking the outputs. The Platzi parser is verified against the user's **real SingleFile** (`~/Downloads/Platzi… .html`) plus a tiny committed synthetic fixture.

**Reference spec:** `docs/superpowers/specs/2026-07-19-aion-design.md`

## Task 2: `/aion-setup` command

**Files:**
- Create: `.claude/commands/aion-setup.md`

- [ ] **Step 1: Define the command contract**

The command, when invoked in Claude Code, must:
1. If `data/` doesn't exist, **create the tree**: `data/`, `data/dias/`, `data/platzi/`.
2. Initialize `data/entrenamiento-log.json`, `data/checkins.json`, `data/aprendizaje.json` as `[]` **only if absent** (never overwrite existing history).
3. Interview the user for: metas, horario fijo (inicio/fin de trabajo), tracker, campo(s) de interés.
4. Ask for the training routine: let the user paste text (write to `data/rutina-entrenamiento.md`) or point to a PDF placed in `data/`.
5. Write/merge `data/perfil.json` (idempotent — update named fields, keep the rest).
6. **Never** copy from `data.ejemplo/`; that folder is reference only.
7. End by confirming what was written and suggesting `/aion` next.

- [ ] **Step 2: Write the command file**

```markdown
---
description: Configura tu perfil de Aion (metas, horario, tracker, campos de interés, rutina)
---

Eres Aion configurándote por primera vez (o actualizando la configuración).

## Pasos

1. **Prepara el almacenamiento.** Sin sobrescribir nada existente:
   - Crea las carpetas `data/`, `data/dias/`, `data/platzi/` si no existen.
   - Crea `data/entrenamiento-log.json`, `data/checkins.json`, `data/aprendizaje.json`
     con contenido `[]` SOLO si aún no existen. Nunca borres historial.
   - NUNCA copies desde `data.ejemplo/` — esa carpeta es solo referencia.

2. **Entrevista breve** (una pregunta a la vez, tono cálido):
   - Metas (lista corta).
   - Horario fijo: hora de inicio y fin de trabajo.
   - Qué tracker de sueño/actividad usa (ej. Apple Watch, Garmin, ninguno).
   - Campo(s) de interés para el resumen de noticias (ej. "Inteligencia Artificial").

3. **Rutina de entrenamiento:** pregunta si prefiere pegar el texto o ya colocó un
   PDF en `data/`. Si pega texto, escríbelo en `data/rutina-entrenamiento.md`.
   Si es PDF, anota la ruta en `data/perfil.json` bajo `rutinaArchivo`.

4. **Escribe `data/perfil.json`** con este esquema (idempotente: si ya existe,
   actualiza solo los campos que cambian y conserva el resto):
   \`\`\`json
   { "camposDeInteres": [], "horarioFijo": { "trabajoInicio": "", "trabajoFin": "" },
     "tracker": "", "metas": [], "rutinaArchivo": null }
   \`\`\`
   (`rutinaArchivo`: ruta al PDF si la rutina es un PDF; `null` si se pegó como texto en `rutina-entrenamiento.md`.)

5. **Confirma** lo que guardaste y dile que ya puede correr `/aion` cada mañana,
   y `/aion-platzi` cuando tenga un SingleFile de su ruta de Platzi.
```

- [ ] **Step 3: Write the command file**

```markdown

description: Lee un SingleFile HTML de tu ruta de Platzi y guarda tu progreso

## Pasos
```

## Task 4: The `aion` skill (reasoning logic)

**Files:**
- Create: `.claude/skills/aion/SKILL.md`

- [ ] **Step 1: Define what the skill encodes**

The skill is the shared brain the commands lean on. It documents: how Aion reads context before asking (routine + week's log + checkins), how the **contextual check-in** works (sleep anchored to tracker; training anchored to routine + week, logging weights per exercise), and the cross-analysis rules (prescribed-vs-done adherence, weight progression / plateau detection, rest-vs-load → today's training window, Platzi-vs-goals → study plan). It also fixes the enums (`suenoCalidad`, `energia`) and the day-plan section contract.

- [ ] **Step 2: Write `SKILL.md`**

```markdown
---
name: aion
description: Lógica del optimizador personal Aion — check-in contextual y armado del día óptimo cruzando descanso, entrenamiento, aprendizaje y noticias.
---

# Aion — cerebro

Antes de preguntar nada, LEE el contexto: `data/perfil.json`,
`data/rutina-entrenamiento.md`, la semana en curso de `data/entrenamiento-log.json`
y los últimos `data/checkins.json` y `data/aprendizaje.json`.

## Check-in contextual (nunca genérico)
- **Sueño:** pregunta las horas y la calidad que marcó su tracker anoche. Guarda
  `suenoHoras` (número) y `suenoCalidad` ∈ "mala"|"regular"|"buena"|"excelente".
  `energia` entero 1–5.
- **Entrenamiento:** mira qué tocaba según la rutina y qué se hizo esta semana.
  Pregunta con contexto ("ayer tocaba Pierna, ¿lo hiciste? ¿qué levantaste en
  sentadilla?") y registra pesos por ejercicio en `data/entrenamiento-log.json`.
- **Contexto:** energía de hoy y algo inusual (trasnoche, viaje, lesión).
- Nunca inventes horas ni pesos: si falta un dato, pregúntalo.

## Cruce
- Adherencia: rutina prescrita vs realizada esta semana.
- Progresión de cargas por ejercicio: ¿subió, se mantuvo, se estancó? Señala estancamientos.
- Descanso reciente vs carga → recomienda ventana e intensidad de entreno hoy.
- Progreso Platzi vs metas → recomienda qué estudiar y cuánto.

## Contrato del plan del día (siempre, en orden)
1. Resumen del día (una línea).
2. Ventana de entrenamiento (hora/intensidad + por qué).
3. Plan de estudio (curso/lección + minutos).
4. Digest del campo (2–4 noticias del campo de interés, con enlace si hay).
5. Adaptaciones (qué cambió hoy y por qué).
Si una sección no aplica (ej. sin internet → sin digest), inclúyela con una nota; no la omitas.
```

- [ ] **Step 3: Verify contract**

Confirm `SKILL.md` has valid frontmatter (`name`, `description`) and covers: context-read step, the three check-in anchors, the four cross-analysis rules, the enums, and the 5-section day contract.
Expected: all present.

- [ ] **Step 4: Commit**

```bash
git add .claude/skills/aion/SKILL.md
git commit -m "feat: add aion reasoning skill"
```
